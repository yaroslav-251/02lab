1. Почему для хранения денег используют decimal, а не double? Что может пойти не так с double?
double хранит дробные числа приблизительно — в двоичном виде, и часть десятичных дробей (например, 0.1) точно представить не получается. Из-за этого появляются микроскопические погрешности: 0.1 + 0.2 даёт не 0.3, а 0.30000000000000004. Для научных расчётов это не критично, но для денег недопустимо — копейки не должны теряться.
2. Что произойдёт, если целочисленный тип (например, byte) переполнится — то есть значение выйдет за границы диапазона?
Значение «обернётся» по кругу. У byte диапазон от 0 до 255. Если к 255 прибавить 1, результат не 256, а 0 — счётчик перескакивает через верхнюю границу и идёт сначала. Это называется переполнение (overflow).
3. Чем var отличается от динамической типизации в Python? В какой момент компилятор определяет тип переменной, объявленной через var?
В Python тип переменной может меняться легко: x = 5, потом x = "текст" — это нормально. Это динамическая типизация.
var в C# — не то же самое. Компилятор смотрит на значение справа от = и один раз, во время компиляции, определяет тип. После этого переменная ведёт себя как обычно: если это int, присвоить туда строку нельзя.
4. Какой тип данных всегда возвращает Console.ReadLine(), независимо от того, что ввёл пользователь?
Всегда string (строку). Даже если пользователь ввёл 42, программа получит текст "42", а не число 42
5. Чем int.Parse отличается от int.TryParse в поведении при некорректном вводе (например, буквы вместо цифр)?
int.Parse — падает с ошибкой FormatException, программа завершается.
int.TryParse — не падает. Возвращает false (не получилось), а в переменную через out записывает 0. Программа продолжает работать.
TryParse — безопасный способ, потому что никогда не «роняет» программу из-за плохого ввода
6. Что означает false, возвращённый из int.TryParse, и что при этом попадёт в переменную, переданную через out?
false означает: превратить строку в число не удалось. Строка не похожа на целое число — например, содержит буквы, знаки препинания или пустая.
В переменную, объявленную через out, при этом попадёт 0 — значение по умолчанию для типа int. То есть TryParse не оставит переменную «пустой» или «неопределённой» — она всегда получит хоть какое-то значение.
7. Приведите пример, когда стоит использовать TryParse, а не Parse — и объясните, почему.
Пример: пользователь вводит свой год рождения через Console.ReadLine(). пользователь может ввести что угодно — «две тысячи», «2006 год», пустую строку, случайные буквы. С Parse программа упадёт и пользователь увидит красный текст ошибки. С TryParse программа не упадёт.
